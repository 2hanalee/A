# City of Elegia — 세계관 소개 사이트 기획서 v0.1

> 작성 기준: 저장소에 있는 실제 자산 전수 분석 (캐릭터 34명 × 8컷 = 272장, 프롤로그 세로 원고 2종, Bikini City 로고)
> 레퍼런스 dembrandt 데이터는 아직 미수령 → 수령 후 v0.2에서 디자인 토큰 확정

---

## 0. 한 줄 정의

**"오로라 유니온 데이터베이스에 접속한 방문자가, 1946년 비키니 환초에서 시작된 이야기를 따라 내려오다 '히어로냐 빌런이냐'를 선택하고, 그 진영의 캐릭터와 대화를 시작하게 만드는 사이트."**

세계관 소개 사이트의 진짜 KPI는 '세계관을 이해했다'가 아니라 **'캐릭터와 대화를 시작했다'** 입니다. 모든 페이지의 동선을 `대화 시작` CTA로 수렴시킵니다.

### 1-2. 캐릭터 DB (카드 34장 판독 → `data/characters.json`)

- **진영**: Hero 22 / Villain 11 / 무소속 1 (엘렌, 등급 X "협회 관찰대상")
- **세력**: 오로라 유니온(Hero Force) 33명, **스파이럴 리전(Invasion Force)** 1명 — 김태양(알파)
- **등급 분포**: S 3 (레이노버스·하윤슬·세인 노바) / A 6 / B 18 / C 5 / D 1 / X 1
- **숨은 드라마 축** (사이트에서 반드시 띄워야 할 것):
  - 레이노버스 = **협회장**, NOVUS-001
  - 도하린 = Hero **(위장)** → 정체 반전 떡밥
  - 비올레타 = Villain **(그레이존)**
  - 강로아(세르핀) ↔ 강리아(세라핀·다크) = **쌍둥이/표리 관계**
  - 류하윤 ↔ 류하늘, 하씨 다수 → 가족 관계 여부 확인 필요
- **이미지 슬롯 규칙** (전 캐릭터 동일): `0` 프로필 카드 / `1–5` 도시 표정·포즈 / `6` 해변(비키니 시티) / `7` 능력 발현

### 1-3. 기존 카드 UI = 이미 완성된 디자인 언어

카드의 HUD 문법(1px 네온 라인, 모서리를 깎은 패널, `THREAT LEVEL`, `AU-ID`, `▶▶▶▶`, 바코드, 영문 라벨+국문 값)이 매우 일관됩니다. **사이트 디자인 시스템은 이 카드에서 출발**하는 게 맞습니다. 외부 레퍼런스는 '레이아웃·리듬·모션'을 배우는 용도로 쓰고, 정체성은 이미 우리 손에 있습니다.

## 3. 사이트 구조 (IA)

```
/                     메인 — 인트로 + 프롤로그 스크롤 + 선택 게이트
├─ /world             세계관 — 기원(1946) · 두 필연 · 도시 엘레지아 · 진영 · 등급 체계 · 용어집
├─ /database          오로라 유니온 DB — 34명 인덱스 (필터: 진영/등급/세력/능력 계열)
│   └─ /database/:id  캐릭터 도시에(dossier) — 대화 시작 CTA
├─ /factions          진영 — 오로라 유니온 / 빌런 / 스파이럴 리전 / 무소속
└─ /bikini-city       비키니 시티 모드 (같은 DB를 여름 테마로 리스킨)
```

### 3-1. 메인 `/` — "선택하라" 동선

1. **콜드 오픈 (0–1 스크린)**: 검은 화면, 타자기처럼 "인간은 늘 믿어왔다…". 스크롤 유도.
2. **프롤로그 6막 (스크롤 스토리텔링)**: 원고 패널을 sticky 레이어로 배치. 1막은 흑백, 3막에서 금(시간)·청(공간)이 좌우에서 충돌하며 컬러가 처음 들어옴 — **색이 곧 서사**.
3. **선택 게이트**: 화면이 좌우로 갈라짐. `AURORA UNION · HERO` / `THREAT · VILLAIN` 두 카드. (스파이럴 리전은 숨겨진 3번째 선택지 — 일정 스크롤/클릭 이스터에그로 해금)
4. 선택한 진영에 따라 **사이트 테마 변수(accent)가 전환**되고, 그 진영의 추천 캐릭터 3명이 등장 → `대화 시작`.
5. 선택은 localStorage에 저장, 재방문 시 "다시 접속을 환영합니다, 요원." 처럼 진영별 인사.

### 3-2. 오로라 유니온 DB `/database`

- 상단: 검색창 형태의 HUD (`QUERY > _`), 필터 칩: 진영 · 등급(S~D, X) · 세력 · 능력 계열(원소/소환/강화/정신/공간)
- 그리드: 카드 썸네일(슬롯 1) + 이름 + 코드네임 + 등급 배지. 호버 시 시그니처 컬러로 테두리 점등 + 대사 한 줄 타이핑.
- **정렬 기본값은 "위협 등급순"** — 세계관상 '협회 DB'라는 설정을 UI가 연기.
- 빌런 카드에는 `CLASSIFIED` 스캔라인, 그레이존/위장 캐릭터는 정보 일부를 `█████` 마스킹 → 클릭 유도.

### 3-3. 캐릭터 도시에 `/database/:id`

| 영역 | 내용 |
|---|---|
| 히어로 | 슬롯 7(능력 발현) 풀블리드 + HTML로 재구성한 카드 패널 |
| 신상 | 코드네임 · 진영 · 등급 · 능력(영/한) · AU-ID · 대사 |
| 표정 갤러리 | 슬롯 1–5 가로 스크롤. "이 캐릭터는 이런 표정도 짓습니다" → 대화 기대감 |
| 관계도 | 쌍둥이(SPA↔SPB), 협회장(NB) 등 연결 노드 *(참치 입력 필요)* |
| 첫 메시지 미리보기 | 채팅 UI 모양으로 첫 대사 1–2개 *(참치 입력 필요)* |
| CTA | `▶ 대화 시작` (캐릭터 채팅 플랫폼 링크) + `ELEGIA / BIKINI` 토글 |

### 3-4. 세계관 `/world`

- 연표형 세로 타임라인: `1946 실험` → `확산` → `각성` → `두 필연의 충돌` → `붕괴` → `재건 / 엘레지아` → `현재 (종말 전야)`
- **등급 체계 설명**: S/A/B/C/D + X(비해당·관찰대상). 히어로에게도 THREAT LEVEL이 붙는 이유(협회가 모든 능력자를 잠재적 위협으로 분류) — 세계관의 긴장감을 만드는 좋은 설정이므로 문장으로 명시 권장.
- 용어집: 오로라 유니온, 스파이럴 리전, AU-ID, 그레이존, 성흔 등.

## 4. 디자인 시스템 초안 (레퍼런스 수령 전 가설)

### 4-1. 컬러

- 베이스: `#05070D`(배경) / `#0B1020`(패널) / `#E8ECF6`(본문) / `#8A93AD`(보조)
- 서사 듀얼: **시간 `#F2B544`** (금) / **공간 `#3D6BFF`** (청) — 로고·구분선·선택 게이트
- 진영: Hero `#4FB3FF` 계열 / Villain `#FF3B5C` 계열 / Spiral `#A77BFF` / Neutral `#E8C66A`
- **캐릭터 시그니처 컬러 34종**: `characters.json`의 `accent` → CSS 변수 `--accent`로 페이지마다 주입

### 4-2. 타이포 (웹폰트, 전부 무료 상업 이용 가능 계열)

| 역할 | 서체 | 근거 |
|---|---|---|
| 국문 UI/본문 | Pretendard Variable | 가독성, 굵기 폭 |
| 국문 서사 자막 | Noto Serif KR (또는 Gowun Batang) | 프롤로그 원고가 명조 계열 박스 자막 |
| 국문 디스플레이(캐릭터 이름) | Pretendard Black + 글로우 / 필요 시 GPT 로고 | 카드의 두꺼운 고딕 네온 느낌 |
| 영문 HUD 라벨 | Chakra Petch 또는 Rajdhani | `CODE NAME`, `THREAT LEVEL` 등 각진 테크 서체 |
| 숫자·ID | JetBrains Mono | `AU-ID : AURA-014` |

### 4-3. 컴포넌트 문법 (카드에서 추출)

- 패널: `clip-path`로 모서리 1~2곳 깎기, 1px 네온 보더 + 바깥 글로우
- 라벨 쌍: 국문 큰 글씨 + 영문 작은 대문자 (진영 / AFFILIATION)
- 장식: `▶▶▶▶`, 사선 해칭 게이지, 바코드, 좌측 세로 눈금 — **장식은 화면당 2개까지**로 제한해 과밀 방지
- 모션: 스캔라인 등장, 숫자 카운트업, 글리치는 빌런 전용

## 5. 기술·운영

- 정적 사이트 (Astro 또는 Next.js SSG) + `characters.json` 단일 소스 → 캐릭터 추가 시 JSON 한 줄 + 이미지 폴더만 추가
- 이미지: 1536×1024 webp → 640/1024/1536 반응형 + AVIF, lazy load. 현재 images 70MB는 빌드 시 자동 최적화
- 프롤로그: 원고를 패널 단위로 분할 (스크립트로 자동화 가능)
- 연령/노출: 슬롯 6(해변) 일부 컷은 노출도가 높음 → 비키니 시티 모드 진입 시 안내 1회, 공유용 OG 이미지는 슬롯 1–5만 사용
